# Трассировка рекурсии F(n)

Исходная функция:

```csharp
static int F(int n)
{
    if (n <= 1) return 1;
    return n * F(n - 1);
}
```

## 1. Базовый случай и шаг рекурсии

- **Базовый случай:** если `n <= 1`, функция возвращает `1` без нового рекурсивного вызова.
- **Шаг рекурсии:** если `n > 1`, функция вызывает `F(n - 1)` и умножает полученный результат на `n`: `F(n) = n * F(n - 1)`.

Для целых неотрицательных `n` функция вычисляет факториал `n!` (пока результат помещается в `int`).

## 2. Ручная трассировка F(4)

Глубину первого вызова считаем равной 0. При движении вниз по стеку каждый вызов ждёт результата следующего:

```text
F(4)
  → F(3)
    → F(2)
      → F(1)
```

| Вызов | Глубина | Возвращает |
| --- | ---: | --- |
| `F(4)` | 0 | `4 * F(3) = 4 * 6 = 24` |
| `F(3)` | 1 | `3 * F(2) = 3 * 2 = 6` |
| `F(2)` | 2 | `2 * F(1) = 2 * 1 = 2` |
| `F(1)` | 3 | `1` — базовый случай |

Возврат значений идёт вверх по стеку в обратном порядке:

```text
F(1) возвращает 1
F(2) возвращает 2 * 1 = 2
F(3) возвращает 3 * 2 = 6
F(4) возвращает 4 * 6 = 24
```

**Результат: `F(4) = 24`.**

## 3. Вызов F(-1) при условии n == 1

Если заменить базовое условие на `if (n == 1) return 1;`, вызов `F(-1)` породит последовательность:

```text
F(-1) → F(-2) → F(-3) → F(-4) → ...
```

Аргумент уменьшается с каждым вызовом и удаляется от `1`, поэтому базовый случай не достигается. Каждый вызов остаётся в стеке и ждёт результата следующего; до умножения и возврата значения выполнение не доходит.

В обычном выполнении стек вызовов исчерпается, что приведёт к **переполнению стека** (`StackOverflowException` в C#) и аварийному завершению программы. Это произойдёт задолго до возможного переполнения самого целочисленного аргумента.

В исходной версии с условием `n <= 1` вызов `F(-1)` сразу возвращает `1`.
